> 評估方法參考 career-ops：A–H 結構化報告 + 全球 1–5 總分（五維質性判斷，非算術平均）。
> G 為獨立貼文合法性評估，不影響總分；H 僅在 4.5+ 才撰寫。
> 評估基準：9 年半導體（製程 7 年 + MES IT 2 年）、陽明交大資科碩專班在學、LLM/Agent 實戰（mini-llm-agent + Hermes）、不具傳統 ML 實證。
> 本評估**僅針對 JD 職責 4–8 的 LLM Serving / AI 後端 / MLOps 線**，職責 1–3（控管圖/良率 ML 模型）屬傳統 ML，依你「AI/ML 我不會」不計入主推。

## A. 職缺本質（Role & Intent）
晶圓廠 AI 工程師，職責混合兩段：前半（1–3）是傳統 ML 的控管圖異常預警、良率/缺陷分析、生產優化模型；後半（4–8）是 LLM 服務化、AI 後端系統、MLOps、生產系統品質。
本評估聚焦後半段「LLM Serving / 製造 AI 後端」線——這是你可投的方向。碩士以上、無需相關工作經驗、ML/LLM 實務「優先」非必備，門檻寬。

## C. 加分條件 match（Nice-to-have）
- 職責 4 建立靈活框架加速 AI 模型開發、專注 LLM serving：◯（mini-llm-agent 即 LLM 應用框架實作）
- 職責 5 把 AI 原型轉產品、用 LLM 等先進技術：◯（你有 MES API 上線 + LLM 專案落地經驗）
- 職責 6 大規模即時數據存取/收集/分析/監控的 AI 後端：⚠️ MES 批次/即時查詢優化有類比，但無大規模串流實證
- 職責 7 建立維護 MLOps（部署/監控/自動化）：✕（缺口，你無 MLOps 實證）
- 職責 8 持續提升 AI 生產系統品質（尤其 LLM）：◯（你有 Human Review / eval / 錯誤 fallback 設計）

## D. 隱性期待（Unstated Expectations）
- 「把 LLM 原型轉成產品」需要工程化與維運思維——你有 MES API 從開發到上線的完整經驗，可對應。
- 「大規模即時數據後端」——MES 現場數據處理經驗提供 domain 直覺，但技術棧（Kafka/串流）需補。
- 工作地點龍潭/新竹/台中/台南——需確認通勤/ relocate 意願。

## E. 匹配度綜合（Fit Synthesis）
優勢在「LLM 實戰 + 半導體 9 年 domain + SDLC 落地」——職責 4/5/8 幾乎為你而寫，且「無經驗可、碩士優先」門檻極寬。
硬傷在「英文流利」與「MLOps / 大規模即時後端」——前者是溝通門檻，後者需補最小實證。
重點：職責 1–3 的 ML 部分你不做，面試要清晰劃線「我投 LLM serving 線，傳統 ML 模型由團隊 ML 成員負責，我負責服務化與後端」。

## F. 風險與缺口（Risks & Gaps）
1. **英文流利差距**：JD 寫 fluent，你自評中級。技術面試若英文進行會吃虧，建議準備英文 self-intro 與專案口述。
2. **MLOps 實證缺失**：職責 7 直接點名，你無 CI/CD/模型監控實證——需用「MES 維運觀念 + LLM 錯誤 fallback」類比，誠實定位學習中。
3. **大規模即時後端**：無串流實證，MES 批量優化經驗僅部分可轉。
4. **傳統 ML 不會**：職責 1–3 全缺，面試須主動劃線，避免被問 ML 模型細節露餡。
